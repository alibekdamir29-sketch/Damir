# DAMIR — premium fashion e-commerce

Интернет-магазин одежды DAMIR: каталог, корзина, оформление заказа, онлайн-оплата через адаптер платёжного провайдера, отслеживание заказов, админ-панель и AI-консультант на Claude API (RU / KZ).

**Стек:** Next.js 15 (App Router) · TypeScript · Tailwind CSS · компоненты в стиле shadcn/ui · Lucide · Prisma · PostgreSQL · Anthropic SDK · Vitest · Playwright.

## Быстрый старт

Нужно: Node.js 20+ и PostgreSQL 14+.

```bash
npm install
cp .env.example .env           # заполните DATABASE_URL и AUTH_SECRET
npm run db:deploy              # применить миграции
SEED_ADMIN_EMAIL=you@mail.kz SEED_ADMIN_PASSWORD='StrongPass123' npm run db:seed   # демо-каталог + админ
npm run dev                    # http://localhost:3000
```

- Магазин: `http://localhost:3000`
- Админ-панель: `http://localhost:3000/admin`

`npm run db:seed` создаёт 11 категорий, 32 товара и около 400 вариантов (цвет × размер) с остатками, а также настройки магазина по умолчанию. Фото в демо-каталоге — сгенерированные силуэты (`public/seed`). Замените их своими фото через админку.

### Как устроен заказ

1. Корзина хранится на сервере, её id лежит в подписанной cookie. При каждом показе цена и наличие берутся из БД.
2. `POST /api/checkout/order` в одной транзакции:
   - пересчитывает сумму и доставку;
   - сверяет итог с тем, что видел покупатель (`PRICE_CHANGED`);
   - **атомарно резервирует** товар условным `UPDATE … WHERE quantity - reserved >= qty`;
   - создаёт номер `DM-ГГГГ-NNNN` и снимок позиций (название, SKU, цвет, размер, цена);
   - очищает корзину.

   Повторная отправка с тем же `idempotencyKey` возвращает тот же заказ.
3. Статусы: `NEW → CONFIRMED / PAYMENT_PENDING → PAID → PROCESSING → SHIPPED → DELIVERED`, отмена возможна до отправки.
   - Отмена снимает резерв.
   - Статус `SHIPPED` списывает товар со склада.
   - Каждое изменение пишется в `order_status_history` и `inventory_movements`.
4. Онлайн-заказ становится `PAID` **только** по подписанному webhook провайдера, с проверкой суммы. Неоплаченные заказы отменяются через `UNPAID_ORDER_TTL_MINUTES`, резерв при этом снимается.

## Как создать администратора

```bash
npm run admin:create -- --email owner@damir.kz --password 'ВашСложныйПароль' --name "Алибек"
# или без пароля в истории shell:
ADMIN_PASSWORD='ВашСложныйПароль' npm run admin:create -- --email owner@damir.kz
```

После этого войдите на `/admin/login`.

Доступ к админке требует двух условий: роль `ADMIN` у пользователя и запись в таблице `admins`. Права проверяются по БД на каждом запросе. Если запустить команду для существующего email, пользователь станет администратором и получит новый пароль.

## Как добавить товары

**Через админку** (`/admin/products` → «Новый товар»):

1. Заполните основные поля:
   - название, SKU, категорию;
   - цену и старую цену (для скидки);
   - описание, материал, состав, сезон, стиль, пол.
2. Отметьте нужные флаги: «Новинка», «Популярное», «Рекомендуем» и т.д.
3. Добавьте цвета (название и HEX) и размеры.
4. Загрузите фото: JPG, PNG или WebP, до 8 МБ. Файл проверяется по содержимому. Первое фото — главное.
5. Сохраните. Варианты «цвет × размер» создаются автоматически.
6. Укажите остатки в `/admin/inventory` или в карточке товара. Каждое изменение попадает в журнал движения с причиной. Остаток нельзя сделать отрицательным или меньше уже зарезервированного.

Категории редактируются в `/admin/categories`. Категорию с товарами удалить нельзя, только скрыть.

**Массово:** используйте `prisma/seed.ts` как шаблон: функцию `createProduct` и формат данных.

## Как подключить AI API

AI-консультант работает на Claude API (Anthropic).

1. Получите ключ на <https://console.anthropic.com> → **API Keys**.
2. В `.env`:
   ```env
   ANTHROPIC_API_KEY="sk-ant-..."
   AI_MODEL="claude-opus-5-5"   # по умолчанию
   ```
3. Перезапустите сервер. В `/admin/settings` появится статус «Подключён».

**Как работает:** модель **не имеет доступа к БД, SQL или админ-функциям**. Она вызывает только контролируемые backend-инструменты (`src/lib/ai/tools.ts`):

- `search_products`, `get_product_details`, `compare_products` — данные из каталога;
- `get_store_info` — доставка, оплата, возврат, контакты из настроек админки;
- `show_products` — карточки в чате, только реальные id;
- `get_cart`, `add_to_cart` — через тот же сервис корзины, что и сайт, с проверкой наличия.

Оформление и оплата заказа происходят только на защищённой странице `/checkout`.

**Ограничения и защита:**

- Ограничения на запросы:
  - 10 сообщений в минуту и 150 в день с одного IP;
  - 1000 символов на сообщение;
  - 40 сообщений в диалоге.
- Промпт инструктирует модель игнорировать попытки prompt-injection.
- Вход каждого инструмента проверяется через zod.
- История хранится в `ai_conversations` и `ai_messages`.

**Стоимость:** системный промпт кэшируется (prompt caching), токены каждого ответа сохраняются в `ai_messages`. Можно указать другую модель через `AI_MODEL`.

## Как подключить платежи

Архитектура — адаптеры (`src/lib/payments/`). Провайдер выбирается переменной `PAYMENT_PROVIDER`. Данные карты **никогда** не проходят через сервер магазина: покупатель вводит их на странице провайдера.

| `PAYMENT_PROVIDER` | Назначение |
|---|---|
| `none` (или пусто) | Онлайн-оплата скрыта. Работают «при получении» и банковский перевод (включаются в `/admin/settings`) |
| `test` | **Только для разработки.** Тестовая страница оплаты с подписанным webhook. В production отключается автоматически |
| `cloudpayments` | Реальные платежи (Казахстан) |

### CloudPayments

1. Заключите договор и получите в личном кабинете **Public ID** и **API Secret**.
2. В `.env`:
   ```env
   PAYMENT_PROVIDER="cloudpayments"
   CLOUDPAYMENTS_PUBLIC_ID="pk_..."
   CLOUDPAYMENTS_API_SECRET="..."
   APP_URL="https://ваш-домен.kz"
   ```
3. В кабинете CloudPayments включите уведомления **Pay** и **Fail** на адрес
   `https://ваш-домен.kz/api/payments/webhook/cloudpayments`.
4. В `/admin/settings` включите «Онлайн-оплата».

Webhook проверяется по подписи `Content-HMAC` (HMAC-SHA256) и по сумме. Повторы обрабатываются идемпотентно.

**Другой провайдер** (Kaspi Pay, Halyk ePay, Stripe и т.д.):

1. Создайте файл в `src/lib/payments/`, реализующий интерфейс `PaymentProvider` из `types.ts`: `createPayment` и `parseWebhook` с проверкой подписи.
2. Зарегистрируйте его в `index.ts`.

Остальная логика (статусы, суммы, идемпотентность) уже общая.

## Как задеплоить

### Вариант A — VPS + Docker

```bash
cp .env.example .env     # заполните; добавьте POSTGRES_PASSWORD=...
docker compose up -d --build
```

Администратора (и при желании демо-каталог) создайте с вашего компьютера, указав `DATABASE_URL` на серверную БД:
`DATABASE_URL=... npm run admin:create -- --email ...` (порт PostgreSQL откройте временно или используйте SSH-туннель).

Миграции применяются автоматически при старте контейнера. Фото хранятся в томе `uploads`. Поставьте перед приложением reverse-proxy с HTTPS (Caddy или Nginx).

### Вариант Railway (проще всего, без терминала)

1. railway.com → New Project → **Deploy from GitHub repo** → этот репозиторий (соберётся по `Dockerfile`).
2. **+ New → Database → PostgreSQL**.
3. Variables сервиса сайта: `DATABASE_URL=${{Postgres.DATABASE_URL}}`, `AUTH_SECRET`, `APP_URL`, `ANTHROPIC_API_KEY`, `PAYMENT_PROVIDER=none`, `UPLOAD_DIR=/data/uploads`, `ADMIN_EMAIL`, `ADMIN_PASSWORD`, `CRON_SECRET`.
4. **Volume** с путём `/data`, чтобы фото не пропадали.
5. Settings → Networking → **Generate Domain** (или свой домен).

Миграции применяются и администратор создаётся автоматически при старте. Вход: `/admin/login`.

### Вариант B — Vercel / Railway / Render + управляемый PostgreSQL (Neon, Supabase и др.)

1. Задайте переменные окружения из `.env.example`.
2. Build command: `npm run build`. Перед первым запуском выполните `npm run db:deploy`.
3. На serverless-хостингах локальная папка `UPLOAD_DIR` не сохраняется. Используйте VPS или Docker с томом, либо замените `src/lib/storage.ts` на S3-совместимое хранилище.

### Обязательно для production

- Длинный случайный `AUTH_SECRET`, HTTPS, корректный `APP_URL`.
- `PAYMENT_PROVIDER` — `cloudpayments` или `none`, но не `test`.
- **Cron** для отмены неоплаченных онлайн-заказов, каждые 10 минут:
  ```bash
  */10 * * * * curl -fsS -X POST -H "Authorization: Bearer $CRON_SECRET" https://ваш-домен.kz/api/cron/expire-orders
  ```
- Регулярные бэкапы PostgreSQL.
- Ограничение частоты запросов хранится в памяти процесса. Если запускаете несколько инстансов, вынесите его в Redis (`src/lib/rate-limit.ts`).

## Тесты

```bash
createdb damir_test                 # отдельная тестовая БД (DATABASE_URL для тестов задаётся TEST_DATABASE_URL)
npm test                            # 31 тест: unit + интеграционные на реальном PostgreSQL
npm run test:e2e                    # Playwright: витрина, checkout, трекинг, защита админки, mobile
```

Покрыто:

- **Склад и гонки:** два покупателя одновременно берут последнюю единицу — продаётся ровно одна.
- **Заказы:** идемпотентность заказа, изменение цены, отмена и отгрузка со снятием и списанием резерва, недопустимые переходы статусов.
- **Корректировка остатков:** нельзя уйти в минус или ниже резерва.
- **Webhook:** неверная подпись, неверная сумма, повтор.
- **Онлайн-оплата:** заказ нельзя отметить оплаченным вручную; неоплаченные заказы истекают.
- **AI-инструменты:** только реальные товары, без админ-инструментов, добавление в корзину с проверкой наличия.

## Безопасность и бизнес-правила

- **Цены, итоги, доставка и наличие** считаются только на сервере. Клиентские значения игнорируются.
- **Нет перепродажи:** атомарный резерв плюс CHECK-ограничения в PostgreSQL (`quantity >= 0`, `reserved <= quantity`).
- **«Оплачено»** показывается только после подтверждённого webhook, онлайн-оплату нельзя подтвердить вручную. Для оплаты при получении статус `PAID` ставится при доставке.
- **Валидация:**
  - zod на всех API;
  - проверка `Origin` для изменяющих запросов (CSRF);
  - httpOnly + SameSite cookie;
  - bcrypt для паролей;
  - заголовки безопасности (CSP, X-Frame-Options и др.).
- **Ограничение частоты:** вход, регистрация, checkout, трекинг, AI.
- **Аудит:** создание заказов, смена статусов, платежи, действия админов (`audit_logs`).
- **Загрузки:** проверка типа по сигнатуре файла и лимит размера.
- **Трекинг заказа:** по номеру + телефону или по секретной ссылке (случайный токен). Чужой заказ по одному номеру не открыть.
